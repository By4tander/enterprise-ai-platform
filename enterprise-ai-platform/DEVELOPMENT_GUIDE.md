## 一、平台概览

### 1.1 平台是什么

**智影 · Agent 工作平台** 是一个企业级多 Agent 协作工作平台。它的核心目标是将 AI 从个人对话工具升级为团队中可协作、可管理、可沉淀的**数字员工**。

> 💡 **一句话理解**: 每个项目 = 一个独立的 AI Agent 工作空间，多个项目并行运行，经验和产出物跨项目沉淀复用。

### 1.2 核心理念

| 维度 | 传统 AI 助手 | 智影平台 |
|------|-------------|---------|
| 🔄 工作模式 | 个人对话窗口 | 多项目并行 Agent 工作区 |
| 📦 知识沉淀 | 对话结束即丢失 | 技能资产跨项目复用 |
| 🎯 技能定制 | 平台方定义 | 自定义导入/蒸馏/创建 |
| 📁 产出管理 | 停留在对话框 | 真实文件自动归档 |
| 👥 团队协作 | 无协作机制 | 部门级权限 + 锁定协作 |
| 🤖 模型绑定 | 绑定单一模型 | 模型无关架构 |

### 1.3 技术架构总览

```
┌──────────────────────────────────────────────────────────────┐
│                    🖥️  Web 前端 (React + TypeScript)          │
│   实时流式对话 · Markdown 渲染 · 文件浏览器 · 可调整面板       │
│   明暗主题 · 拖放交互 · 跨项目状态隔离                        │

                         ▼

## 二、环境搭建与启动

### 2.1 系统要求

| 依赖 | 最低版本 | 说明 |
|------|---------|------|
| Node.js | >= 18 | 前端构建运行 |
| Python | >= 3.10 | 后端运行 |
| npm | >= 9 | 前端包管理 |
| AI Agent CLI | 已安装 | Hermes CLI（可选，无则使用模拟器） |

### 2.2 代码克隆

```bash
git clone https://github.com/By4tander/enterprise-ai-platform.git
cd enterprise-ai-platform
```

### 2.3 后端启动

```bash
# 进入后端目录
cd backend

# 创建 Python 虚拟环境
python -m venv venv
source venv/bin/activate  # macOS/Linux
# venv\Scripts\activate   # Windows

# 安装依赖
pip install -r requirements.txt

# 初始化种子数据（首次运行）
python seed_data.py

# 启动后端服务
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

> ⚠️ **首次启动** 会自动创建 SQLite 数据库文件 `backend/storage/app.db`，并执行增量迁移。

### 2.4 前端启动

```bash
# 进入前端目录（新终端窗口）
cd frontend

# 安装依赖
npm install

# 启动开发服务器
npx vite --host 0.0.0.0 --port 5173
```

> 💡 启动后访问 `http://localhost:5173` 即可打开平台。局域网内其他设备可通过 `http://<你的IP>:5173` 访问。

### 2.5 一键启动脚本

项目根目录提供 `start.sh` 脚本，可同时启动前后端：

```bash
chmod +x start.sh
./start.sh
```

### 2.6 环境变量配置

后端环境变量文件位于 `backend/.env`：

```env
# Hermes CLI 路径（根据实际安装位置修改）
HERMES_CLI_PATH=/Users/yourname/.local/bin/hermes

# 单次对话超时时间（秒）
HERMES_TIMEOUT_SECONDS=600

# 最大并发 Hermes 进程数
MAX_CONCURRENT_HERMES=3

# JWT 密钥（生产环境必须修改！）
# JWT_SECRET_KEY=your-production-secret-key

# 技能蒸馏 API Key（留空则使用模拟模式）
# DISTILLATION_API_KEY=sk-xxx

# 调试模式
DEBUG=True
```

> 🔒 **安全提醒**: 生产环境务必修改 `JWT_SECRET_KEY` 和 `CORS_ALLOW_ALL` 配置！

    │   ├── files.py              #   文件：上传/浏览/沙盒文件树
    │   ├── folders.py            #   文件夹：管理 + 集群记忆
    │   └── locks.py              #   锁定：协作锁定 + 转移请求
    ├── models/                   # SQLAlchemy ORM 模型
    │   ├── user.py               #   用户模型（3种角色）
    │   ├── department.py         #   部门模型

    │   ├── skill.py              #   技能模型（global/department）

    │   ├── auth.py               #   认证相关 Schema
    │   ├── project.py            #   项目相关 Schema
    │   ├── message.py            #   消息相关 Schema
    │   ├── skill.py              #   技能相关 Schema
    │   ├── user.py               #   用户相关 Schema

### 4.3 登录流程

```
用户输入用户名密码
        │
        ▼
POST /api/auth/login
        │
        ▼
验证用户名存在 ──不存在──→ 返回 401 "用户名或密码错误"
        │ 存在
        ▼
验证密码（bcrypt）──不匹配──→ 返回 401 "用户名或密码错误"
        │ 匹配
        ▼
生成 JWT Token（HS256，8小时有效期）
        │
        ▼
返回 TokenResponse:
  - access_token: JWT 令牌
  - user_id: 用户ID
  - username: 用户名
  - role: 角色
  - department_id: 部门ID
  - department_name: 部门名称
        │
        ▼
前端存储到 localStorage:
  - access_token
  - user（用户信息对象）
        │
        ▼
跳转到仪表盘页面
```

> 💡 **安全设计**: 登录失败时，错误信息统一为"用户名或密码错误"，不区分是用户名不存在还是密码错误，防止用户名枚举攻击。

### 4.4 注册流程

注册接口 `POST /api/auth/register` 支持以下字段：

| 字段 | 必填 | 说明 |
|------|------|------|
| `username` | ✅ | 用户名（唯一） |
| `password` | ✅ | 密码 |
| `display_name` | ❌ | 显示名称 |
| `email` | ❌ | 邮箱 |
| `department_id` | ❌ | 部门ID |

注册逻辑：
1. 检查用户名是否已存在 → 409 冲突
2. 如果指定了 `department_id`，验证部门是否存在 → 400
3. 使用 bcrypt 哈希密码
4. 创建用户记录
5. 返回 JWT Token（注册即登录）

### 4.5 Token 刷新机制

```
GET /api/auth/me
Authorization: Bearer <token>
        │
        ▼
验证 Token 有效性 ──无效──→ 返回 401
        │ 有效
        ▼
返回当前用户信息

POST /api/auth/refresh
        │
        ▼
基于当前用户信息生成新 Token
        │
        ▼
返回新的 TokenResponse
```

> 💡 Token 有效期为 **8 小时**。前端在收到 401 响应时会自动清除本地存储并跳转到登录页。

| 接口 | 方法 | 权限 | 说明 |
|------|------|------|------|
| `/api/departments/` | GET | 所有用户 | 获取部门列表（含用户数和项目数统计） |
| `/api/departments/` | POST | 超级管理员 | 创建部门（名称唯一） |

## 十一、三级技能体系

技能体系是平台的核心资产沉淀机制，分为三个层级：

```
┌─────────────────────────────────────────────┐
│            🌐 全局原生技能                    │  ← Agent 自主调用
│         终端操作 / 文件系统 / API 调用 / ...   │
├─────────────────────────────────────────────┤
│            🏛️ 部门技能                       │  ← 部门资产，跨项目共享
│         配音脚本 / 风格分析 / 数据处理 / ...   │
├─────────────────────────────────────────────┤
│            📁 项目技能                        │  ← 当前项目专用
│         导入的 / 蒸馏的 / 自定义的            │
└─────────────────────────────────────────────┘
```

### 11.1 全局原生技能

- **来源**: Hermes CLI 内置技能 + 用户上传的全局技能
- **存储**: 文件系统 `~/.hermes/skills/` + 数据库 `scope=global`
- **管理**: 仅超级管理员可上传和管理
- **调用**: Agent 自主决定是否调用

### 11.2 部门技能

- **来源**: ZIP 导入 / 手动创建 / 项目蒸馏
- **存储**: 数据库 `scope=department` + 文件系统 `~/.hermes/skills/{department_id}/`
- **管理**: 部门管理员可导入、审批、设置默认注入
- **审批机制**: 普通成员提交的技能需要管理员审批后才能使用

**技能属性**:

| 属性 | 说明 |
|------|------|
| `skill_name` | 技能名称 |
| `content_prompt` | 技能内容（Markdown 格式） |
| `category` | 技能分类 |
| `is_approved` | 是否已审批 |
| `auto_inject` | 是否自动注入到所有对话 |
| `rating` | 技能评分（1-5 星） |
| `usage_count` | 使用次数 |
| `import_source` | 导入来源（manual/zip/distillation） |

### 11.3 项目技能

- **来源**: 对话中引用的技能 / 项目特定的技能文件
- **存储**: 项目沙盒 `.hermes/skills/` 目录
- **生命周期**: 随项目存在，项目归档后可蒸馏为部门技能

### 11.4 技能导入

技能导入弹窗支持三种导入模式：

**模式一：粘贴内容**
- 文本区域粘贴 JSON、YAML 或 Markdown
- JSON: 解析技能对象数组，显示名称和内容预览
- Markdown: 按 `# ` 标题分割，每个标题成为一个技能
- 预览最多显示 5 个技能

**模式二：上传文件**
- 拖放区域支持 `.json`、`.yaml`、`.yml`、`.md` 文件
- 读取文件内容后显示预览

**模式三：ZIP 技能包**
- 拖放区域支持 `.zip` 文件
- 支持的格式标识：
  - WorkBuddy 格式
  - Claude Code 格式
  - OpenAI Codex 格式
  - OpenClaw 格式
  - 通用格式
- 自动解析 ZIP 包中的 `SKILL.md` 和元数据文件
- 同步到 Hermes 技能目录

**ZIP 解析流程**:
1. 解压到临时目录
2. 遍历查找 `SKILL.md` 和 `.md` 文件
3. 检测格式（WorkBuddy / Claude Code / 通用）
4. 提取 YAML frontmatter 元数据
5. 写入 Hermes 技能目录 `~/.hermes/skills/{department_id}/{skill_name}/`
6. 创建数据库记录

### 11.5 技能搜索

全局技能搜索功能，跨三个来源搜索：

1. **Hermes 原生技能**: 从文件系统扫描
2. **全局数据库技能**: `scope=global` 的记录
3. **部门数据库技能**: `scope=department` 的记录

搜索逻辑：关键字匹配技能名称、描述、分类（不区分大小写）。

### 11.6 技能蒸馏

当项目归档时，可自动将项目经验蒸馏为可复用技能：

**蒸馏流程**:
1. 加载项目信息、所有消息、所有产出物
2. 构建蒸馏输入（对话文本上限 8000 字符，产出物上限 8000 字符）
3. 调用 LLM（GPT-4o 或模拟模式）
4. 解析 JSON 响应为技能列表
5. 保存到 `department_skills` 表（`is_approved=False`，需管理员审批）

**蒸馏输出四类技能**:

| 类别 | 说明 |
|------|------|
| 🎯 高效指令模式 | 从对话中提取的有效提示词模式 |
| 📋 工作流模板 | 可复用的 SOP 流程 |
| 📚 领域知识沉淀 | 特定领域的专业知识 |
| ⚠️ 踩坑经验 | 问题-解决方案对 |

## 十四、SSE 实时推理流

### 14.1 通信协议

平台使用 **Server-Sent Events (SSE)** 实现实时流式对话：

- **传输方式**: `POST /api/chat/stream`（注意是 POST，不是 GET）
- **为什么不用 EventSource**: 原生 `EventSource` 仅支持 GET 请求，无法携带 Authorization Header 和请求体
- **实现方式**: 自定义 `fetch` + `ReadableStream` 解析器

**请求格式**:
```json
{
  "project_id": "uuid",
  "content": "用户消息内容",
  "show_thinking": true,
  "file_paths": ["/path/to/file1.txt"],
  "attachments": [{"name": "file.txt", "size": 1024}]
}
```

**响应头**:
```
X-Accel-Buffering: no        # 禁用 nginx 缓冲
Cache-Control: no-cache, no-store, must-revalidate
Pragma: no-cache
Connection: keep-alive
```

### 14.2 事件类型详解

| 事件类型 | 数据格式 | 说明 |
|---------|---------|------|
| `status` | `{"type":"status","content":"连接已建立"}` | 连接状态通知 |
| `thinking` | `{"type":"thinking_chunk","content":"思考内容片段"}` | Agent 推理过程流式片段 |
| `content` | `{"type":"content_chunk","content":"回复内容片段"}` | Agent 主回复流式片段 |
| `queue` | `{"type":"queue","content":"队列位置: 2"}` | 并发排队位置通知 |
| `tool_call` | `{"type":"tool_call","content":"工具调用信息"}` | 工具调用通知 |
| `tool_result` | `{"type":"tool_result","content":"工具返回结果"}` | 工具执行结果 |
| `context` | `{"type":"context","content":"Token/模型统计"}` | 上下文统计信息 |
| `done` | `{"type":"done","message_id":"msg-uuid"}` | 流式传输完成 |
| `error` | `{"type":"error","content":"错误信息"}` | 错误通知 |

### 14.3 连接健康监控

前端实现了两级健康检测机制：

| 阈值 | 时间 | 行为 |
|------|------|------|
| 延迟警告 | 30 秒无数据 | 显示"连接延迟"指示器 |
| 超时断开 | 120 秒无数据 | 自动断开连接，显示"连接超时" |

- **检查频率**: 每 5 秒检查一次
- **检查逻辑**: 对比上次收到数据的时间与当前时间

### 14.4 断线重连机制

**后台流继续**: 切换项目时，SSE 连接在后台继续运行，不会中断。消息保存到数据库。返回项目时检测完成状态并重新加载。

**客户端断开处理**: 当客户端断开连接时，后端收到 `asyncio.CancelledError`，调用 `bridge.kill()` 终止 Hermes 子进程。

平台使用**双重机制**确保不遗漏任何产出物：

**机制一：沙盒快照对比**
1. 对话开始前，记录项目沙盒中所有文件的快照
2. 对话结束后，再次扫描沙盒文件
3. 对比差异：新增或修改的文件（排除 `attachments/` 目录）自动注册为产出物

**机制二：文本内容提取**
- 从 Agent 回复的文本内容中提取结构化产出物
- 支持自定义标签格式、代码块、章节标题

### 15.2 产出物提取规则

| 优先级 | 格式 | 说明 |
|--------|------|------|
| 1（最高） | `` ```artifact title="..." file_type="..." `` `` | 自定义产出物标签 |
| 2 | `` ```language ... `` `` | 标准代码块（≥ 80 字符） |
| 3 | `## 标题` + 内容 | 章节标题（≥ 200 字符，排除常见非产出物标题） |

**排除的章节标题**: "思考过程"、"总结"、"分析"、"结论"、"备注" 等。

**去重逻辑**: 按 `(project_id, title)` 去重，同名产出物更新内容和时间戳。

### 15.3 文件类型过滤

产出物面板支持按文件类型过滤，每个类型显示为一个药丸形按钮并附带对应的 emoji 图标。

## 十七、协作锁定机制

### 17.1 锁定状态

| 状态 | 颜色 | 含义 |
|------|------|------|
| 🟢 编辑中 | 绿色 | 有用户正在编辑（显示用户名） |
| 🟡 只读 | 琥珀色 | 有用户正在编辑，其他人只读 |
| ⚪ 空闲 | 灰色 | 无锁定，可直接编辑 |

> ⚠️ 锁定状态存储在**内存中**，服务器重启后所有锁定丢失。

### 17.2 锁定获取与释放

**获取锁定** (`POST /api/locks/acquire`):
1. 超级管理员 → 强制获取（踢出当前编辑者）
2. 项目无锁定 → 直接获取
3. 同一用户 → 续期时间戳
4. 不同用户 → 返回拒绝 + 当前编辑者名称

**释放锁定** (`POST /api/locks/release`):
- 仅锁定所有者或超级管理员可释放
- 项目离开时自动释放

### 17.3 锁转移请求

当项目被其他人锁定时，可发起锁转移请求：

1. 点击"请求编辑"按钮
2. 系统创建待处理请求（UUID 标识）
3. 当前编辑者收到请求通知
4. 当前编辑者可选择：
   - ✅ **批准**: 锁定转移给请求者
   - ❌ **拒绝**: 请求被驳回

**轮询机制**: 每 5 秒检查一次待处理的转移请求。

### 17.4 管理员强制接管

超级管理员可以强制接管任何项目的锁定：

- 绕过所有检查
- 当前编辑者被踢出
- 操作按钮："管理员接管"（仅超级管理员可见）

1. 获取文件夹内所有活跃项目
2. 收集每个项目的 `MEMORY.md` 文件
3. 收集每个项目最近 20 条消息
4. 写入组合摘要 `cluster_memory_summary.md`
5. 调用 Hermes CLI 分析摘要并生成技能文件
6. 扫描生成的 `.md` 文件（上限 5 个技能）
7. 重建所有项目的符号链接

**Hermes CLI 调用**:
- 工作目录：文件夹目录
- 超时时间：300 秒
- 输出格式：带 YAML frontmatter 的 `.md` 文件

## 十九、Hermes Agent 桥接层

### 19.1 桥接架构

```
后端 (FastAPI)
    │
    ▼
HermesCLIBridge
    │
    ▼
hermes_stream_bridge.py (通过 Hermes 的 Python 解释器运行)
    │
    ▼
Hermes CLI 进程（子进程，NDJSON 流输出）
    │
    ▼
DeepSeek API / 其他 LLM
```

### 19.2 进程启动流程

1. **并发控制**: 获取信号量槽位（最大并发 3）。如果排队，发送 `queue` 事件
2. **沙盒隔离**: 获取项目沙盒目录和环境变量
3. **命令构建**: 通过 Hermes 的 Python 解释器运行 `hermes_stream_bridge.py`
4. **文件附件注入**: 读取附件内容（每个最大 500KB），注入到系统提示中
5. **进程环境**: 设置关键环境变量
6. **启动子进程**: `asyncio.create_subprocess_exec()`

**关键环境变量**:
| 变量 | 说明 |
|------|------|
| `PYTHONUNBUFFERED=1` | 强制立即刷新 stdout |
| `LANG=en_US.UTF-8` | UTF-8 编码 |
| 移除所有代理变量 | 防止本地代理拦截 DeepSeek API 调用 |

### 19.3 NDJSON 流解析

**解析策略**: 原始字节缓冲区

1. 从 stdout 读取 64 字节块到原始字节缓冲区
2. 按 `\n`（0x0A）字节分割行
3. 解码每行为完整 UTF-8 字符串
4. 解析 JSON

> 💡 **为什么用字节缓冲区**: UTF-8 多字节字符可能跨越读取边界。由于 `\n`（0x0A）永远不会出现在 UTF-8 多字节序列中，按 `\n` 分割可以安全地保证每行是完整的 UTF-8 字符串。

### 19.4 ANSI 清洗

Hermes CLI 输出可能包含 ANSI 转义码，清洗逻辑包括：

| 清洗内容 | 说明 |
|---------|------|
| ANSI 转义码 | `\033[...m` 等 |
| 退格覆盖 | `\b` 字符 |
| 回车覆盖 | `\r` 字符 |
| Braille 旋转字符 | Unicode 盲文进度指示器 |
| 终端查询序列 | `\033[...n` 等 |
| 不可打印控制字符 | 其他控制字符 |

### 19.5 Think 标签解析

Hermes 输出中的 `<think>...</think>` 标签被解析为思考内容：

```python
{
    "before": "标签前的文本",
    "thinking": "思考过程内容",
    "after": "标签后的文本"
}
```

### 19.6 并发控制

使用 `asyncio.Semaphore` 实现并发限制：

- **最大并发数**: 3（可配置）
- **信号量获取**: 返回队列中的位置（0 = 立即执行，>0 = 排队等待）
- **活跃任务跟踪**: 线程安全的计数器（`asyncio.Lock`）
- **上下文管理器**: 支持 `async with manager as position:` 语法

**属性**:
| 属性 | 说明 |
|------|------|
| `active_jobs` | 当前运行的任务数 |
| `waiting_jobs` | 当前排队的任务数 |
| `available_slots` | 可用槽位数 |

### 19.7 模拟器回退

当 Hermes CLI 不可用时，使用模拟器提供降级体验：

**关键词匹配响应**:
| 关键词 | 响应类型 |
|--------|---------|

| "代码" | 代码相关模拟回复 |

## 二十、上下文组装器

### 20.1 三层注入策略

上下文组装器将三层技能注入到系统提示中：

```
系统提示 = [第1层: 全局技能] + [第2层: 部门技能] + [第3层: 项目上下文] + [用户输入]
```

**第 1 层：全局技能**
- 查询 `scope="global"` 且 `is_approved=True` 的技能
- 关键字匹配：技能名称或分类出现在用户输入中
- `auto_inject=True` 的技能始终包含
- 上限 8 个技能
- 匹配后递增 `usage_count`

**第 2 层：部门技能**
- 查询 `scope="department"`、匹配 `department_id`、`is_approved=True` 的技能
- 同样的关键字匹配 + 自动注入逻辑
- 上限 10 个技能
- 添加匹配指示器：🔍 关键字匹配 / ⚙️ 自动注入

**第 3 层：项目上下文**
- 包含 `project.system_prompt_override`（如果设置了）
- 包含最近 40 条项目历史消息
- 消息格式：`**用户**: ...` 或 `**Agent**: ...`

### 20.2 技能匹配算法

```python
def _match_skills(skills, user_input, max_count):
    matched = []
    for skill in skills:
        # 1. 关键字匹配：技能名称（或其分词）或分类出现在用户输入中
        if keyword_in_input(skill.name, user_input) or \
           keyword_in_input(skill.category, user_input):
            matched.append(skill)
        # 2. 自动注入：auto_inject=True 的技能始终包含
        elif skill.auto_inject:
            matched.append(skill)
    # 3. 去重（按技能 ID）
    matched = deduplicate(matched)
    # 4. 截断到 max_count
    return matched[:max_count]
```

### 20.3 历史消息裁剪

- **最大历史消息数**: 40 条
- **裁剪策略**: 取最近 40 条消息
- **目的**: 防止上下文窗口溢出

## 二十五、开发注意事项与最佳实践

### 25.1 安全注意事项

| 事项 | 风险等级 | 说明 |
|------|---------|------|
| 🔴 JWT 密钥 | 高 | 开发默认密钥，生产环境必须修改 |
| 🔴 CORS 配置 | 高 | `CORS_ALLOW_ALL=True`，生产环境需限制 |
| 🟡 文件路径校验 | 中 | `/api/files/content` 端点未严格校验路径 |
| 🟡 锁定状态 | 中 | 内存存储，重启丢失，建议迁移到 Redis |
| 🟢 密码哈希 | 低 | 使用 bcrypt，安全性良好 |
| 🟢 项目 ID 校验 | 低 | 严格的正则校验和路径穿越检测 |

### 25.2 性能优化建议

| 问题 | 建议 |
|------|------|
| N+1 查询 | `list_projects` 和 `list_departments` 需要优化为 JOIN 查询 |
| 无分页 | 技能和产出物接口应添加分页支持 |
| 锁定轮询 | 建议迁移到 WebSocket 推送替代 5 秒轮询 |
| 文件扫描 | 大型沙盒的文件扫描可能较慢，考虑增量更新 |

### 25.3 已知问题

| 问题 | 说明 |
|------|------|
| `create_artifact` 端点 | 函数体以 `pass` 结尾，缺少返回语句 |
| 数据库迁移 | 手动 SQL 迁移无版本管理和回滚能力 |
| macOS 特定路径 | 配置中的路径在其他操作系统上需要 `.env` 覆盖 |
| 硬编码路径 | `HERMES_CLI_PATH` 和 `HERMES_PYTHON_PATH` 需要根据环境修改 |

### 25.4 扩展指南

**添加新功能的标准流程**:

1. **后端**:
   - 在 `app/models/` 中添加 ORM 模型
   - 在 `app/schemas/` 中添加请求/响应 Schema
   - 在 `app/api/` 中添加路由端点
   - 在 `app/services/` 中添加业务逻辑
   - 在 `app/main.py` 中注册新路由

2. **前端**:
   - 在 `services/api.ts` 中添加 API 方法
   - 在 `pages/` 中添加页面组件
   - 在 `App.tsx` 中添加路由
   - 在 `utils/permissions.ts` 中添加权限键

3. **添加新权限**:
   - 在 `permissions.ts` 的 `PERMISSIONS` 表中添加新权限键
   - 设置各角色的权限值
   - 在组件中使用 `hasPermission(role, 'new.perm')` 控制 UI 可见性
   - 在后端使用 `require_role` 依赖控制 API 访问

## 附录 B：常见问题 FAQ

### Q1: 启动后提示"Hermes CLI not found"？

**A**: 这是正常的。如果未安装 Hermes CLI，平台会自动使用模拟器模式。模拟器提供基础的对话体验，适合功能演示和界面测试。

如需使用真实的 AI Agent，请：
1. 安装 Hermes CLI
2. 修改 `backend/.env` 中的 `HERMES_CLI_PATH` 和 `HERMES_PYTHON_PATH`

### Q2: 前端启动后页面空白？

**A**: 检查以下几点：
1. 后端是否已启动（`http://localhost:8000` 应返回健康检查）
2. 浏览器控制台是否有 CORS 错误
3. 是否已运行 `seed_data.py` 初始化数据库

### Q3: 如何切换深色/浅色主题？

**A**: 点击顶栏右侧的设置图标 → 外观设置 → 选择深色模式或浅色模式。

### Q4: 项目归档后可以恢复吗？

**A**: 可以。进入"Agent 资源中心" → "归档工作流"标签页 → 点击"恢复工作流"按钮。

### Q5: 技能蒸馏什么时候触发？

**A**: 在归档项目时，如果勾选了"生成技能"选项，系统会自动在后台触发技能蒸馏。蒸馏完成后，生成的技能需要部门管理员审批后才能使用。

### Q6: 如何导入外部技能包？

**A**: 有三种方式：
1. 在"Agent 资源中心"点击"导入技能"按钮
2. 在"全局技能浏览页"点击上传按钮（仅管理员）
3. 支持粘贴内容、上传文件、ZIP 包三种模式

### Q7: 集群记忆是什么？

**A**: 集群记忆是将同一文件夹内多个项目的经验自动蒸馏为共享技能的功能。管理员可以在文件夹上触发集群记忆蒸馏，蒸馏后的技能会通过符号链接自动对文件夹内所有项目可用。

### Q8: 任务队列有什么用？

**A**: 当 Agent 正在处理一个任务时，你可以继续输入新的消息。这些消息会进入任务队列，当前任务完成后自动执行下一个。你还可以拖拽调整队列顺序或取消队列中的任务。

### Q9: 为什么我的技能没有被自动注入？

**A**: 技能注入需要满足以下条件之一：
1. 技能的 `auto_inject` 属性为 `True`（管理员设置）
2. 用户消息中包含与技能名称或分类匹配的关键字
3. 技能的 `is_approved` 属性为 `True`

### Q10: 如何添加新部门？

**A**: 使用超级管理员账号登录 → 通过 API 调用 `POST /api/departments/` 创建新部门。目前前端暂无部门管理界面，需要通过 API 操作。
